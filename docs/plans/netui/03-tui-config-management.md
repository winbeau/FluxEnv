# 03｜netui TUI 与 JSON 配置管理

## 1. 产品目标

`netui` 的中心不是“代理开关页面”，而是一个以配置 JSON 为核心的管理器：

- 自动看到配置目录里的全部 JSON。
- 快速知道哪个是默认、哪个正在运行、哪些无效。
- 通过少量按键设置默认并决定是否重启。
- 在同一界面选择全局代理、大陆白名单直连或关闭环境变量，并看到当前有效状态。
- 不要求用户记住文件路径或手动改 symlink。
- 以大量但有层级的圆角矩形组织状态、列表、详情和确认弹窗。
- 不泄露配置中的认证字段。

## 2. TUI 技术方案

### 主路径：bundled gum

Release 按架构携带固定版本 `gum`，从包内绝对路径调用，不依赖系统 PATH：

- `gum style --border rounded`：标题、状态卡片、列表容器、详情面板和提示。
- `gum choose`：配置选择和动作菜单。
- `gum confirm`：重启、归档、迁移等确认。
- `gum spin`：批量校验和连通性检查。
- `gum table` 或预格式化列表：配置总览。

优点：界面美观、键盘体验稳定、Bash 业务层保持简单。

### 降级路径：纯 Bash/ANSI

下列情况必须仍可使用：

- gum 丢失或架构不支持。
- `TERM=dumb`。
- 终端尺寸太小。
- gum 运行失败。

降级菜单至少支持：列表、设置默认、校验、启动、停止、环境模式、日志、退出；不能变成只读模式。无 gum 时使用 `╭─╮│╰─╯` 字符保持圆角视觉层级。

### 圆角视觉规范

- 最外层使用一个圆角应用框。
- 顶部至少有三个独立圆角状态卡：运行状态、默认/运行配置、环境模式。
- 配置列表与选中项详情分别置于圆角面板；宽终端左右双栏，窄终端上下堆叠。
- 确认、错误、迁移和模式选择使用圆角 modal，不用裸文本堆在列表下方。
- footer 快捷键提示放入低对比度圆角条。
- 避免每一行都套框导致噪声；圆角框对应信息分组，而不是装饰性滥用。
- 所有边框字符宽度需在目标字体和 CJK/SSH 终端中做截图检查。

## 4. 配置列表语义

### 标记

- `★`：默认配置。
- `●`：当前运行配置。
- 同一行同时有 `★●`：默认和运行一致。
- 默认与运行不同：顶部显示“重启后切换”的警告。
- `✗`：JSON 或 sing-box 校验失败。

### 列

MVP 固定列：

1. 标记。
2. 配置文件名。
3. outbound 协议。
4. 本地监听地址/端口。
5. 校验状态。
6. 修改时间；宽度不足时隐藏。

服务端地址不放主列表，避免屏幕录制/截图中无意泄漏；只在详情页按需展示，并明确标注“本机敏感信息”。

### 排序

- 默认配置置顶。
- 其余按文件名稳定排序。
- 不按协议自动重命名或重新排序用户文件。

## 5. 核心动作

### 5.1 设置默认 `D`

流程：

1. 校验选中配置。
2. 失败时拒绝设为默认，并展示精简错误。
3. 成功后原子切换 `default.json`。
4. 若没有运行实例：提示“下次 netup 使用此配置”。
5. 若当前运行的就是该配置：提示“默认与运行一致”。
6. 若另一配置正在运行：询问：
   - 仅设置默认，暂不重启；
   - 设置默认并重启；
   - 取消。

默认选项应是“仅设置默认”，避免意外断网。

### 5.2 启动默认 `U`

- 调用与 `netup` 完全相同的函数。
- 选中行不是默认时仍启动默认项，不偷偷启动选中项。
- 若用户想启动选中项，必须先设默认；TUI 可提供组合操作“设默认并启动”。

### 5.3 停止 `X`

- 调用与 `netdown` 完全相同的函数。
- 显示当前运行 basename。
- 幂等停止。

### 5.4 重启默认 `R`

- 先验证默认配置。
- 停止当前受管实例，再启动默认配置。
- 启动失败时明确报告；如果旧实例已停，不虚假显示成功。
- 后续可做自动回退到旧运行配置，MVP 不必隐藏失败过程。

### 5.5 校验 `V`

- 默认校验选中项。
- 提供“校验全部”动作。
- 批量校验使用 spinner，并缓存到本次 TUI 会话；文件 mtime 改变后缓存失效。

### 5.6 环境模式 `P`

三选一：

1. 全局代理：`no_proxy=localhost,127.0.0.1,::1`。
2. 大陆白名单直连：精简、去重且 `<=512` bytes 的 `no_proxy`。
3. 关闭环境变量。

TUI 显示模式 preference、当前有效状态、本地 endpoint 和 `no_proxy` 长度。代理未运行时可保存 preference，但有效状态为 OFF；下次 `netup` 后自动应用。退出 TUI 后由 shell prompt hook 更新父 shell，详见 [04-environment-profiles.md](./04-environment-profiles.md)。

### 5.7 日志 `L`

- 显示最近 N 行，默认 80 行。
- 提供继续刷新或返回。
- 不自动执行外网请求。
- 详情页不打印配置内容。

## 6. 配置管理动作

用户的主要目标是管理多个 JSON，因此首个公开版本建议包含以下受控 CRUD。

### 6.1 导入 `I`

- 输入本地文件路径。
- 只接受普通文件，拒绝 FIFO/设备/目录。
- 先复制到 `umask 077` 的临时文件。
- 运行两级校验。
- 让用户确认目标 basename，确保 `.json` 后缀。
- 以 `600` 原子安装，冲突时默认不覆盖。
- 原文件保持不变。

可额外支持把 JSON 内容粘贴到临时编辑器，但不应从命令行参数传秘密。

### 6.2 重命名 `N`

- 校验新 basename。
- 不能覆盖现有配置。
- 如果重命名默认项，原子更新 `default.json`。
- 如果重命名正在运行的配置，只更新本地展示映射；不重启进程，运行快照保留原始 resolved 信息并提示重启。

### 6.3 归档 `A`

第一版不做不可恢复的直接删除：

- 移到 `~/.local/state/netui/backups/config-trash/<timestamp>/`。
- 默认项不能直接归档；必须先选择替代默认或明确进入“无默认”状态。
- 运行项不能归档，需先停止。
- 提供本次会话内撤销或单独“恢复归档”菜单。

### 6.4 编辑 `E`（可在 M2 后半实现）

- 使用 `${EDITOR:-vi}` 打开备份副本。
- 编辑完成先校验，再原子替换原文件。
- 校验失败时保留原配置并让用户选择继续编辑或放弃。
- 不在 shell command string 中拼接文件名。

如果时间受限，编辑可延后，但导入、重命名、归档与设置默认应保留。

## 7. 详情页与脱敏

详情页可展示：

- 文件路径。
- 文件 mode/mtime。
- JSON/sing-box 校验结果。
- inbound 类型与监听。
- outbound 类型、TLS、REALITY 是否启用。
- 服务端 hostname/port（本机按需显示）。
- 是否默认、是否正在运行。

始终隐藏或替换：

```text
password      -> <hidden>
uuid          -> <hidden>
private_key   -> <hidden>
public_key    -> <hidden>
short_id      -> <hidden>
token         -> <hidden>
```

字段名可能使用 snake_case 或 camelCase，脱敏逻辑应覆盖常见变体。最安全的默认是只构造允许字段摘要，而不是先打印整个 JSON 再删除敏感字段。

## 8. 协议识别

从 JSON 内容提取 outbound 类型：

- 单 outbound：显示其 `type`。
- 多 outbound：优先显示具有服务器地址的第一个代理 outbound，并用 `+N` 标记其余项。
- VLESS 且 `tls.reality.enabled=true`：显示 `vless/reality`。
- 无法识别：显示 `unknown`，但仍以 `sing-box check` 判断配置是否有效。

绝不根据 `hy2`、`vless` 等文件名片段推断协议。

## 9. 终端体验要求

- 进入 TUI 前检查 stdin/stdout 均为 TTY。
- 捕获 `INT`、`TERM`、`EXIT`，恢复光标和终端状态。
- 终端 resize 后刷新布局。
- 宽度不足时降级为单列列表，不截断状态含义。
- 支持方向键和 `j/k`；危险动作不能只靠单键立即执行。
- 所有页面提供明确返回/退出键。
- 不使用持续高频刷新；动作后或用户 F5 时刷新，避免 SSH 会话闪烁。
- 宽度 `>=100` 列使用列表/详情双栏圆角布局；80–99 列上下布局；低于 80 列进入紧凑模式。
- 对齐、圆角、颜色和 CJK 字宽必须通过 VHS 固定 viewport 截图验证，而不是只靠人工在当前终端观察。

## 10. TUI 验收场景

1. 空配置目录：显示引导，不崩溃；`netup` 返回“没有默认配置”。
2. 一个有效 JSON：可一键设默认并启动。
3. 三个有效 JSON：全部显示，协议识别准确。
4. 一个损坏 JSON：仍出现在列表，标红且不能设默认。
5. 默认 symlink 损坏：顶部明确报错，允许重新设置。
6. 默认 A 正在运行，改默认 B：显示 A running / B default，不自动断线。
7. gum 缺失：自动进入功能完整的 Bash fallback。
8. 终端宽度 70：信息降级但主要动作可用。
9. 配置名带空格/中文：可列出、选择、设置默认，不发生命令注入。
10. 导入/重命名冲突：不覆盖原文件。
11. 三种环境状态可选择，退出 TUI 后当前 bash/zsh 在下一个 prompt 正确加载/清除变量。
12. 120 列、80 列和 70 列截图中圆角边框闭合、无错位、无内容溢出。
13. 全局与大陆白名单模式弹窗显示正确 `no_proxy` 长度，且不把整串域名塞满主界面。
